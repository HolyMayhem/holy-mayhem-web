# Holy Mayhem

Персональное портфолио независимого разработчика: Next.js App Router, TypeScript, Tailwind CSS, Motion и Lucide. Главная, каталог с фильтрами и отдельные страницы проектов на русском и английском. Полностью статический экспорт, без базы данных и серверного API.

## Запуск

Требуется Node.js 22+ и npm.

```sh
npm ci
npm run dev
```

Откройте http://localhost:3000. Для проверки готового экспорта:

```sh
npm run build
npm run preview
```

`preview` — небольшой локальный HTTP-сервер для папки `out/`; для публикации он не нужен. Другой порт: `PORT=4173 npm run preview`.

## Проверки

```sh
npm run typecheck
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E-тесты проверяют готовый статический экспорт. Они покрывают RU/EN-маршруты, фильтры, смену языка с сохранением страницы, предпочтение языка при возврате на `/`, мобильное меню с клавиатурой, реальные изображения, метаданные, 404, sitemap, доступность через axe и ширины 360–1440 px. Playwright сам запускает preview на порту 4173. HTML-отчёт: `npx playwright show-report`. Скриншоты: `test-results/home-*.png`.

TypeScript 6.0.3 и ESLint 9.39.5 выбраны как стабильные версии, совместимые с установленным `eslint-config-next`. Более новые основные версии пока не поддерживаются его парсером и плагинами. Версии зафиксированы в `package-lock.json`; используйте `npm ci`.

## Структура

```text
src/
  app/                         маршруты, sitemap, robots, корневая 404
    (default)/                 русские адреса без префикса
    (localized)/[locale]/      /ru и /en, локализованный HTML lang
  components/
    home/                      секции главной
    projects/                  карточка, каталог, общий шаблон продукта
    layout/                    шапка, подвал, меню и переключатель языка
    motion/                    анимации и prefers-reduced-motion
    ui/                        небольшие общие элементы
  config/                      настройки сайта и социальных ссылок
  content/                     проекты и словари интерфейса
  lib/                         выбор проектов, валидация, i18n и SEO
  types/                       контракт данных проекта
public/images/                 локальные WebP и изображения для соцсетей
```

Серверные компоненты используются для страниц и содержимого. Клиентские компоненты ограничены фильтрами, анимациями, меню, языковым переключателем и обработкой ошибок.

## Контент и дизайн

- Проекты: `src/content/projects.ts`.
- Тексты интерфейса: `src/content/dictionaries.ts`.
- Социальные сети: `src/config/socials.ts`.
- GitHub, поддержка, домен: `src/config/site.ts`.
- Визуальные токены, композиция и responsive: `src/app/globals.css`.
- Шрифты Manrope (включая кириллицу) и Space Grotesk подключены через `next/font`, отдаются с сайта. Доступ к Google Fonts нужен при первой сборке, но не посетителю.

В `socialLinks` можно добавить Instagram, YouTube или произвольную ссылку. Поддерживаемые иконки: `telegram`, `github`, `instagram`, `youtube`, `link`. Компоненты менять не требуется. Системные иконки — Lucide; брендовые SVG вынесены отдельно, поскольку актуальный Lucide не включает логотипы соцсетей.

## Добавление проекта

Добавьте объект в `projectData` в `src/content/projects.ts`. Порядок задаёт `order`, размещение на главной — `featured`. Не нужно добавлять страницы или менять навигацию.

Минимальный пример:

```ts
{
  id: "my-tool",
  slug: "my-tool",
  name: "My Tool",
  category: "apps", // apps | services
  status: "development", // available | development | archived
  accent: "#A99BD8",
  featured: false,
  order: 40,
  content: {
    ru: {
      summary: "Короткое достоверное описание.",
      tagline: "Краткий заголовок страницы.",
      description: ["Полное описание продукта."],
      seo: { title: "My Tool — Holy Mayhem", description: "Описание для поиска." },
    },
    en: {
      summary: "A short, factual description.",
      tagline: "A short page headline.",
      description: ["A full product description."],
      seo: { title: "My Tool — Holy Mayhem", description: "Search description." },
    },
  },
}
```

Необязательные поля:

| Поле | Формат |
| --- | --- |
| `logo`, `cover` | `{ src, width, height, alt: { ru, en } }` |
| `screenshots` | массив объектов изображений |
| `content.ru.features`, `content.en.features` | массив `{ title, description }` |
| `platforms` | массив названий платформ |
| `links` | массив `{ kind, url }`; kind: `website`, `download`, `github`, `telegram` |
| `sources` | ссылки на источники подтверждённых сведений |

Изображения помещаются в `public/images/`, в `src` указывается путь `/images/...`. Используйте локальные оптимизированные WebP и реальные размеры. `alt` должен описывать изображение на обоих языках. Для логотипов в карточке alt пустой, поскольку название продукта находится рядом; на странице продукта используется содержательный alt.

`validateProjects` проверяет уникальность ID и slug, формат slug, локализации, статусы, категории, цвет, порядок, изображения, возможности и HTTPS-ссылки. Некорректный контент останавливает сборку с сообщением. Пустые или отсутствующие галерея, возможности, платформы и ссылки не выводят пустых разделов. Без обложки показывается декоративная векторная графика, не имитирующая скриншот.

После добавления и сборки появятся `/ru/projects/my-tool/`, `/en/projects/my-tool/` и русский алиас `/projects/my-tool/`, запись в каталоге и sitemap. `featured: true` также добавит проект на главную.

Для будущей CMS сохраните контракт `Project` и замените источник в `src/lib/projects.ts` на адаптер. Сетевая загрузка может выполняться при сборке. Компоненты не зависят от конкретного хранилища.

## Языки и адреса

Русский — основной. Канонические страницы: `/ru/`, `/ru/projects/`, `/ru/projects/[slug]/` и их английские аналоги `/en/...`. `/`, `/projects/` и `/projects/[slug]/` — рабочие русские алиасы с canonical на `/ru/...`; они исключены из sitemap, чтобы не дублировать страницы.

Переключатель сохраняет текущую страницу и открывает её перевод с начала, записывая язык в localStorage. Якорь предыдущего раздела не переносится. Внутренняя навигация всегда использует текущий языковой префикс. При повторном открытии `/` сохранённый английский язык переводит на `/en/`. Если хранилище недоступно, ссылки продолжают работать. Cookies и middleware не нужны.

У русских и английских документов отдельные корневые layout: корректный `html lang` есть уже в статическом HTML. Для единой 404 при нескольких root layout включён флаг Next.js `experimental.globalNotFound`. Он используется только для страницы отсутствующего адреса; основной сайт полностью статический.

## SEO и деплой

Перед публикацией скопируйте `.env.example` в `.env.local` и укажите **реальный** домен:

```dotenv
NEXT_PUBLIC_SITE_URL=https://your-domain.example
NEXT_PUBLIC_BASE_PATH=
```

Без настройки домена используется `http://localhost:3000`, чтобы не выдавать предполагаемый адрес за опубликованный. Эти значения встраиваются при сборке. После смены домена или base path обязательно пересоберите сайт.

```sh
npm ci
npm run build
```

Загрузите **содержимое `out/`** на любой статический хостинг с поддержкой `index.html` в директориях и `404.html`. Не включайте SPA rewrite всех путей на главную: у страниц есть собственные HTML-файлы. Можно использовать GitHub Pages, Cloudflare Pages или Vercel со статическим output. Не загружайте исходники и `.env.local` в папку публикации.

Для GitHub Pages в подкаталоге, например `https://username.github.io/repository/`:

```dotenv
NEXT_PUBLIC_SITE_URL=https://username.github.io
NEXT_PUBLIC_BASE_PATH=/repository
```

Затем пересоберите и публикуйте `out/`. Для предпросмотра такой сборки передайте такой же `NEXT_PUBLIC_BASE_PATH` в окружение preview. Пустой `.nojekyll` уже включён в экспорт для публикации через ветку GitHub Pages.

Публикация этого репозитория настроена через GitHub Actions: `.github/workflows/pages.yml` собирает сайт и публикует только `out/` при push в `main` или ручном запуске workflow. Адрес: https://holymayhem.github.io/holy-mayhem-web/. В настройках Pages выбран источник **GitHub Actions**; домен и base path сборка получает из `actions/configure-pages`.

Основной знак бренда — стеклянный крест `cinematic` (вариант №2). Все три варианта, исходный крест и промпты сохранены в `assets/brand/`; инструкция — `assets/brand/README.md`. Для переключения достаточно изменить `active` в `assets/brand/variants.json` и выполнить `npm run build` или перезапустить `npm run dev`. Подготовка PNG/WebP, favicon и Apple Touch запускается автоматически; отдельно — `npm run brand:prepare`. Компоненты и метаданные используют общую конфигурацию `src/config/brand.ts`.

Есть уникальные title/description для страниц продуктов, canonical, RU/EN hreflang с x-default, Open Graph, Twitter Cards, sitemap и robots. Изображения OG и иконки уже включены. Перегенерация: `python3 scripts/create-social-images.py` (Pillow; в скрипте указаны системные пути к шрифтам macOS, при другой ОС замените их).
